# Branding and Sidebar Menu Controls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Clinic admins set the install's name, logo, colours and sidebar wording inside Clinicoro. This is ported
from the base template's Branding and Sidebar menu screens.

**Architecture:**
- **Storage.** One row in a new `app_branding` table holds the branding. A `null` column means "Clinicoro default",
  so an untouched install looks exactly as it does today.
- **Pure helpers.** `src/lib/branding.ts` holds the types and defaults. It also has the CSS builder (branding to a
  `<style>` string scoped to `data-mode`) and the menu resolver (nav groups plus overrides give the visible menu),
  all unit-tested with vitest.
- **Applying it.** `BrandingProvider` (`src/hooks/use-branding.tsx`) loads the row, caches it in `localStorage`
  and injects the style. A small boot script applies the cached CSS before hydration, so the page doesn't flash.
- **Screens.** Two new Settings sections, `branding` and `menu`, only for owners and admins.

**Tech Stack:** Next.js 16 (App Router), Supabase (Postgres + RLS), next-intl, Tailwind tokens in
`src/app/globals.css`, lucide-react, vitest.

## Global Constraints
- **Branch:** `feat/branding` (off `clinicoro_v0.1`). Nothing is pushed. The migration is **not** applied by Claude;
  the owner runs it in the Supabase SQL Editor.
- **Migration `supabase/migrations/046_app_branding.sql`:**
  - **Table:** `app_branding(id smallint primary key default 1 check (id = 1), title text, subtitle text, logo text,
    sidebar_bg text, sidebar_text text, sidebar_accent text, title_color text, subtitle_color text, theme_primary
    text, theme_text text, theme_muted text, theme_bg text, theme_surface text, theme_danger text, menu jsonb not
    null default '{}'::jsonb, updated_at timestamptz not null default now(), updated_by uuid references
    auth.users(id) on delete set null)`.
  - **Checks:**
    - every colour is null or matches `^#[0-9A-Fa-f]{6}$`;
    - `title` is at most 40 characters and `subtitle` at most 40;
    - `logo` is null, or `https://…` of at most 2000 characters, or `data:image/(png|jpeg|svg+xml|webp);base64,…` of at
      most 700000 characters (512 KB of file is about 683 KB as base64).
  - **Seed:** `INSERT … (id) VALUES (1) ON CONFLICT DO NOTHING`.
  - **RLS:**
    - select for `anon, authenticated` using `true`;
    - update using and with check
      `EXISTS (SELECT 1 FROM profiles p WHERE p.user_id = auth.uid() AND p.account_role IN ('owner','admin'))`;
    - no insert or delete policy.
  - **Trigger:** sets `updated_at = now()` and `updated_by = auth.uid()` on update.
  - It ends with `NOTIFY pgrst, 'reload schema';` and is idempotent (`IF NOT EXISTS`, `DROP POLICY IF EXISTS`).
- **Menu JSON shape:** `{ items?: { [href]: { label?: string; icon?: string; group?: string; hidden?: boolean } },
  groups?: { [groupId]: { label?: string } } }`.
  - Labels are at most 40 characters.
  - `icon` must be a key of `BRAND_ICONS` (a curated lucide map in `src/lib/branding-icons.ts`).
  - Unknown hrefs, groups or icons are ignored when resolving.
  - `/dashboard`, `/settings` and `/access-control` can never be hidden (the resolver ignores `hidden` for them, and
    the UI disables the switch).
  - Moving an item into another group puts it at the end of that group, before the designation order applies.
- **Order and visibility rules stay as they are:**
  - The order inside groups still comes from designation permissions (`sidebarModules`).
  - Visibility is (designation allows it) AND (not hidden).
- **Colours:**
  - **Light mode** applies every set colour by overriding these tokens on `html[data-mode="light"]`:
    - `--primary`, `--ring`, `--chart-1` ← `theme_primary`;
    - `--foreground`, `--card-foreground` ← `theme_text`;
    - `--muted-foreground` ← `theme_muted`;
    - `--background` ← `theme_bg`;
    - `--card` ← `theme_surface`;
    - `--destructive` ← `theme_danger`;
    - `--sidebar` ← `sidebar_bg`;
    - `--sidebar-foreground` ← `sidebar_text`;
    - `--sidebar-primary`, `--sidebar-ring` ← `sidebar_accent`;
    - `--brand-title` ← `title_color`;
    - `--brand-subtitle` ← `subtitle_color`.

    When `theme_primary` is set, light mode also derives:
    - `--primary-hover: color-mix(in oklab, <p> 85%, black)`;
    - `--primary-soft: color-mix(in oklab, <p> 12%, transparent)`;
    - `--primary-soft-2: color-mix(in oklab, <p> 22%, transparent)`.

    The selector must beat `html[data-theme="clinicoro"]`, so use `html[data-mode="light"][data-brand]`; the provider
    sets `data-brand` on `<html>` whenever a branding style is active.
  - **Dark mode** applies only the accent: `--primary`, `--ring`, `--chart-1`, `--sidebar-primary` and
    `--sidebar-ring` ← `theme_primary` (else `sidebar_accent`), plus the derived hover and soft tokens. Surfaces stay
    navy.
  - **Accent picker:** the per-device accent picker in Appearance is removed. `data-theme` is pinned to `clinicoro`;
    the boot script no longer reads `wacrm.theme.v2`. The light/dark mode toggle stays.
- **Name and logo** appear in:
  - the sidebar logo row (`t("title")` is replaced by `branding.title ?? t("title")`, plus the subtitle when set);
  - the mobile nav header;
  - the `(auth)` layout card;
  - `document.title`: the root `metadata.title.template` becomes `%s`, and the provider sets the title suffix as
    `— <title>`. The default stays "Clinicoro".

  When `logo` is set, an `<img>` is drawn in the `Logo` slot (object-contain, same box); otherwise the Clinicoro SVG.
- **Who:** the Settings rail shows `branding` and `menu` only when `canManageMembers`. The panels are read-only if the
  user isn't an admin (defence in depth; RLS is the real guard).
- **i18n:**
  - every new UI string goes in `messages/en.json` under `Settings.branding.*` and `Settings.menu.*`;
  - `messages/ko.json` gets the same keys with the English text (a translation is a later task);
  - `Sidebar.*` keys are unchanged.
- **Tests:** `npm test` (vitest) and `npm run typecheck` must pass. `npm run lint` must have no new errors.
- **Commits:** follow each task's commit step, ending with the session's attribution line.

## Review Focus
1. **An install that has never saved branding** (the row is all null): it looks pixel-identical to today in light
   and dark mode, including the sidebar, buttons and focus rings, and the login page shows "Clinicoro".
2. **A logo that is too big or not an image** (a 600 KB PNG, a `.pdf` renamed `.png`, an `http://` link) is refused
   in the UI with a clear message, before any save. The database check refuses anything that slips through.
3. **The menu after a designation removes a module** that was renamed or moved: it isn't shown. Overrides never make a
   hidden-by-permission page appear.
4. **A non-admin member** opens `/settings?tab=branding` directly: they see no editable controls. An update attempted
   from the console is refused by RLS.
5. **Dark mode after setting a light page background** (for example `#FFF7ED`): dark surfaces stay navy. Only the
   accent changes, and text stays readable.
